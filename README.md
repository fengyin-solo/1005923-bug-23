# 光伏电站运行维护管理平台

面向电站台账、组串阵列、逆变器、汇流箱、跟踪支架、组件清洗、告警处置与发电结算的一体化光伏电站运行维护工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pv-plant-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 跟踪支架：复位/润滑专域规则

跟踪支架不走通用的「改状态字符串」流转，专域逻辑在 `frontend/src/api/tracker-service.ts`：

- **复位并润滑是一次动作、一笔事务**：角度偏差、限位状态、支架状态写进同一份支架记录，
  同时闭环在办偏差台账、在巡视侧复核台账落一行；多份数据先在内存备齐再一次性落库，
  落库后逐份回读校验，任何一份写不成或两处偏差数对不上，整笔退回，不留半台。
- **限位没复位不许润滑**：旧的「完成润滑」直调入口保留为护栏，限位报警时当场拦截并提示
  缺「复位限位」这一步。
- **在办偏差不重复**：同一支架、同一读数、同一天的登记只产生一条事件，连点两次复位也
  不会多出行；支架页点行进详情面板可查在办偏差、历史读数与复核记录。
- **历史值与当前值**：老数据里挤在同一格的「当前/历史」读数在首次打开时迁移拆开
  （结构版本 `tracker_schema_version`），当前值为准、历史值保留在「历史偏差记录」，
  数值对不上的历史版本在表格和详情里打 ⚠ 标记。
- **驱动机构权限**：支架页选定「本班专责方阵」后，只能改本方阵支架的驱动电机，跨方阵
  一律退回。
- **复核台账**：复位结果落到巡视检查页底部的「跟踪支架复位复核台账」，支架侧待复核偏差数
  与台账偏差合计实时对账，对不上时新动作会被拦截；巡视侧确认复核再核销两边。
- **润滑周期**：从「上次润滑时间」按周期天数补算到期日，兼容没有这些字段的既有支架
  （坏周期按 90 天、缺上次润滑时间按已到期处理）。
